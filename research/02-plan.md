## 1. Цель проекта

**Бизнес-цель:** сайт, который превращает посетителя с телефона в запись.
**Учебная цель:** пройти полный цикл, как в реальной веб-студии: исследование → план → PRD → дизайн → вёрстка → проверка → публикация.

**Как поймём, что сайт хороший (критерии успеха):**
- Кнопка «Записаться» видна на любом экране телефона.
- Запись оформляется ≤ 4 шагов и ≤ 90 секунд.
- Цена и длительность видны у каждой услуги.
- Lighthouse (проверка в Chrome): Производительность ≥ 90, Доступность ≥ 95 на мобильном.
- Сайт корректно выглядит на ширине 360 px (телефон), 768 px (планшет), 1440 px (компьютер).

## 2. Кто клиент (кратко)

| Сегмент | Что важно | Что показать на сайте |
|---|---|---|
| Новая клиентка, 22–40 лет, нашла через карты/соцсети | Стиль работ, цена, отзывы, близко ли | Галерея, прайс, рейтинг, карта |
| Постоянная клиентка | Быстро записаться к «своему» мастеру | Кнопка записи + выбор мастера |
| Покупатель подарка | Сертификат | Блок «Подарочный сертификат» |

### Этап 3. PRD — «техническое задание» на сайт
Что войдёт:
1. Название салона и короткое позиционирование (предложу 3–5 вариантов на выбор).
2. Описание каждого из 13 блоков: что в нём, какой текст, какая кнопка, как ведёт себя на телефоне.
3. Прайс: список услуг с ценами и временем (придуманные, но реалистичные).
4. Мастера (3–4), отзывы (6–8), FAQ (6–8 вопросов).
5. Логика записи: шаги формы, поля, что происходит после отправки.
6. Требования: скорость, доступность, адаптивность, SEO, 152-ФЗ.
7. Что **не** делаем в первой версии.
- Результат: `research/03-prd.md`
- **Твоё участие:** выбрать название и подтвердить состав блоков.

### Этап 4. Дизайн-концепция
1. Палитра — 2–3 варианта на выбор (например: «Молочный френч», «Пудра + бордо», «Нюд + шалфей»).
2. Шрифты: заголовки (антиква с кириллицей: Cormorant Garamond / Prata), текст (Manrope / Onest).
3. Стиль фото, кнопок, карточек, отступов (дизайн-токены).
4. Превью первого экрана (hero) в 2 вариантах — ты выбираешь.
- Результат: `research/04-design.md` + страница-превью
- **Твоё участие:** выбрать палитру и вариант первого экрана.

### Этап 5. Вёрстка
Структура файлов:
```
vs.001/
├── index.html          ← новый сайт
├── privacy.html        ← политика обработки персональных данных
├── css/style.css
├── js/main.js
├── images/             ← сжатые фото (WebP)
├── research/           ← документы проекта
├── index-old.html      ← старый сайт (не трогаем)
└── instruction.txt
```
Порядок (каждый шаг — показываю тебе результат):
1. Каркас: HTML-структура всех блоков, шапка, футер.
2. Стили: цвета, шрифты, сетка — **сначала мобильная версия**, потом планшет и компьютер.
3. Блоки по очереди: Hero → Преимущества → Услуги и цены → Галерея → Мастера → Отзывы → Стерильность → Акции → FAQ → Запись → Контакты.
4. Липкая кнопка «Записаться» на мобильном.
5. Интерактив (JS): меню-бургер, вкладки прайса, фильтр и просмотр галереи, FAQ-аккордеон, форма записи по шагам, анимации появления.
6. Форма записи: проверка полей, чекбокс согласия на ПД, после отправки — экран «Спасибо» + кнопка «Написать в Telegram».
7. SEO: заголовки, описания, микроразметка `NailSalon`, favicon, превью для соцсетей.

### Этап 6. Проверка
Чек-лист:
- [ ] Телефон 360 px / планшет / компьютер — ничего не «едет», нет горизонтальной прокрутки
- [ ] Все кнопки «Записаться» ведут в запись
- [ ] Телефон кликабельный, карта открывается
- [ ] Форма: нельзя отправить без имени, телефона и согласия
- [ ] Lighthouse: Производительность ≥ 90, Доступность ≥ 95
- [ ] Контраст текста достаточный, всё работает с клавиатуры
- [ ] Фото сжаты, грузятся «лениво»
- Результат: отчёт о проверке (что прошло, что нет — честно).

### Этап 7. Публикация (обсудим отдельно)
- Варианты: бесплатный хостинг (Netlify / GitHub Pages / Vercel) или российский хостинг + домен.
- Для настоящего салона: подключить реальную онлайн-запись (YCLIENTS/DIKIDI), отправку заявок в Telegram, Яндекс Метрику.

## 4. Что НЕ делаем в первой версии

- Личный кабинет клиента и онлайн-оплата.
- 3D, AR-примерка ногтей, AI-фишки (дорого и тормозит).
- Многостраничный сайт и блог — позже, если понадобится.
- Реальная отправка заявок на сервер — пока форма работает в демо-режиме (без бэкенда).

## 5. Риски и как их закрываем

| Риск | Что делаем |
|---|---|
| Стоковые фото выглядят «не по-настоящему» | Подбираем в одном стиле; в коде пометка «заменить на реальные работы» |
| Тяжёлые фото → медленный сайт | WebP, правильные размеры, ленивая загрузка |
| Форма без бэкенда не отправляет заявки | Честно помечаем демо-режим; на этапе 7 — Telegram-бот или виджет записи |
| Юридические требования (152-ФЗ) | Шаблон политики + чекбокс; для реального салона — проверить у юриста |
| «Перегруз» анимациями | Только появление блоков и лёгкие hover-эффекты; учитываем настройку «уменьшить движение» |
